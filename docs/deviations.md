# Deviations from the legacy workflow

Every change that makes our numbers differ from the legacy pipeline must be listed here, with
evidence and a test that quantifies its effect. Until an entry is marked **Adopted**, the code
reproduces legacy behaviour (possibly behind a `legacy=True` switch).

Status: **Candidate** (suspected, not yet confirmed) → **Confirmed** (demonstrated with a test)
→ **Adopted** (fixed in default behaviour) / **Rejected**.

| X14 | Adopted (D13; `processing.py`) | Boundary histograms (edge assignment) | Particles are put on an edge if they lie beyond the output grid's outer half-cell, then binned along the edge with `np.histogram2d` over the grid cells. | X18 | Confirmed | Integration window | The 2019 runs integrated each field over 721 h ending at the first sounding's release, so for later soundings the first part of the backward trajectory (closest to the receptor) fell outside the window. The development Python version of the script (`python-in_progress/satellite/date_backruns_satellite.py:318`, written by ACRC summer interns, committed once in Oct 2019, apparently never used for production) still has the bug. | `name_input.run_timing(integration="all_releases")` (default) makes the window cover every release and every particle's full 720 h; `"legacy_2019"` reproduces the old one. | `name_input.py`; dev/scripts/process_stage1.py |
